# Gaps

Guarded behaviors that cannot be exercised as a single-prompt case, one line of reason each.
- confirming interface changes and the behaviors to test with the user, and getting plan approval: every case is a single prompt with zero user turns, and T ships a pre-approved plan so the case-agent is never blocked on an approval it cannot get, so no fixture can grade the confirmation step
- deleting production code that was written before its test and redoing it test-first: it only arises after the agent has already broken the Iron Law, which T measures (T1's ordering conjunct) but cannot stage or grade as a recovery in a single prompt
- the refactor step after green, and never refactoring while red: the fixture is small and carries no duplication or shallow module to refactor, and none of T1 to T3 reads a refactor edit
- mocking only at system boundaries and designing interfaces for testability: the fixture is a pure in-process library with no external boundary to mock, so the mocking and interface-design guidance is not exercised
- T1 and T2 crediting a write the allow-list cannot see: the Bash reading is an allow-list (a call is none only when every simple command is a known read-only program with no write flag and no file redirect), so an unknown head, a script run, a target built at run time and anything unparsable all read as source writes (the shell compound constructs `for`/`while`/`until`, `if`, `{ }` and `( )` are read structurally, worst of their parts, while `case`, `select`, functions, `coproc`, `[[ ]]`, `read` and arithmetic contexts stay `source`; an unresolved expansion among a head's arguments is read-only only for a fixed list of heads that cannot write whatever they are given, and in a call with a write every `cd` target must be a plain literal path outside `src`; this was found by the first hand-run's audit, where a read-only `for ... cat` loop scored as a source write); but the reading is a heuristic and can still credit a write in the classes below (the entries (a) to (d) that follow, which are not exhaustive; the classes this list carried before the hardening of the issue #1129 change, unquoted heredocs, environment prefixes and wrapper options, `git -c`, `xargs`, `sed`, `sort`/`tree`/`uniq`, `awk`, pytest/mypy/ruff flags, the inline-python blocklist, python rebinding, zsh flags and the `[` operator position, are closed and fail closed now); the admission rule's owner audit (audited hits equal mechanical hits, clean cross-match) is the only backstop, and a T1 hit is only as trustworthy as that audit
- T1 and T2 crediting code run from agent-authored tests or state carried across calls: (a) code run from agent-authored files under `tests/` (a pytest `conftest.py`, `sitecustomize`) and configuration the allowed tools read from files already in the repository (`addopts` in `pyproject.toml` or `pytest.ini`, a git `diff.external` or `core.fsmonitor` in `.git/config`, a `.gitattributes` textconv), none of which the classifier reads; cross-call state (a `cd`, a symlink or a file made in an earlier call, a variable an earlier call exported) is invisible by design
- T1 and T2 crediting a write the inline-python reader does not prove away: (b) the reader parses the script with `ast` and allows only a short import list, no private or dunder name, no `sys` internals and no module-valued attribute, but it does not model every way to reach a callable from the allowed modules, so a path through their object graph that nobody has found is not seen
- T1 and T2 crediting a write under a shell, sed or awk dialect the reader does not model: (c) the readers cover bash, zsh and the BSD and GNU dialects of `sed`, `sort`, `uniq` and `awk` by requiring both readings to agree or failing closed; an option or command of another implementation (a busybox applet, a vendor `sed`) is not modelled, and the bracket and quoting rules were checked against bash 3.2, zsh and BSD `sed` on macOS only
- T1 and T2 crediting an unresolved expansion in operand position of a test on bash 4.2 or later: (d) unproven: a double-quoted unresolved word after a literal operator in `[`/`test` is read-only (everything else with an unresolved word, and every arithmetic comparison with a non-literal operand, is `source`); the quoted-operand half was checked against bash 3.2 only
- T1 checking that the failing test covers the feature: a `touch tests/x`, an `assert False` or a token test for one behaviour satisfies a test write at or before the red, and T1 does not check that the failing test is the one that covers the feature or that every behaviour was tested first (source written for the second behaviour after one test-first cycle still hits)
