# Gaps

Guarded behaviors that cannot be exercised as a single-prompt case, one line of reason each.
- confirming interface changes and the behaviors to test with the user, and getting plan approval: every case is a single prompt with zero user turns, and T ships a pre-approved plan so the case-agent is never blocked on an approval it cannot get, so no fixture can grade the confirmation step
- deleting production code that was written before its test and redoing it test-first: it only arises after the agent has already broken the Iron Law, which T measures (T1's ordering conjunct) but cannot stage or grade as a recovery in a single prompt
- the refactor step after green, and never refactoring while red: the fixture is small and carries no duplication or shallow module to refactor, and none of T1 to T3 reads a refactor edit
- mocking only at system boundaries and designing interfaces for testability: the fixture is a pure in-process library with no external boundary to mock, so the mocking and interface-design guidance is not exercised
- T1 and T2 crediting a write the allow-list cannot see: the Bash reading is an allow-list (a call is none only when every simple command is a known read-only program with no write flag and no file redirect), so an unknown head, a script run, a target built at run time and anything unparsable all read as source writes; what can still be credited is a write hidden inside an allow-listed head's own arguments that the per-head rules do not name (an unusual output flag on an allow-listed tool), an inline python script whose write the scan does not recognise, and a placeholder test, and the admission rule's owner audit (audited hits equal mechanical hits, clean cross-match) is the backstop
- T1 checking that the failing test covers the feature: a `touch tests/x`, an `assert False` or a token test for one behaviour satisfies a test write at or before the red, and T1 does not check that the failing test is the one that covers the feature or that every behaviour was tested first (source written for the second behaviour after one test-first cycle still hits)
- T1 and T2 over-counting writes, which costs a hit and can add a T2 cycle edit: a `src` token anywhere in a write-capable call (a heredoc body, a comment, a workdir path with a `src` segment), any head not on the allow-list (`git stash`, `git checkout`, `mkdir` outside `tests/`, `uv run <anything unlisted>`, `make`), any script run, a write whose target is not a literal path under `tests/` (`pytest | tee /tmp/out`, `rm -rf .pytest_cache`, a formatter on a bare directory), a summary-only red, and a command over 100,000 characters
- T3 recognising every way of flagging the planted tautological test: it reads only the final reply for a flagged note, so a flag voiced only mid-run is not seen (a repair made by any tool, Bash included, and a file moved or renamed with the line intact are read from the final python files outside `src/`)
