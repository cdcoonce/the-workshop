# Gaps

Guarded behaviors that cannot be exercised as a single-prompt case, one line of reason each.
- confirming interface changes and the behaviors to test with the user, and getting plan approval: every case is a single prompt with zero user turns, and T ships a pre-approved plan so the case-agent is never blocked on an approval it cannot get, so no fixture can grade the confirmation step
- deleting production code that was written before its test and redoing it test-first: it only arises after the agent has already broken the Iron Law, which T measures (T1's ordering conjunct) but cannot stage or grade as a recovery in a single prompt
- the refactor step after green, and never refactoring while red: the fixture is small and carries no duplication or shallow module to refactor, and none of T1 to T3 reads a refactor edit
- mocking only at system boundaries and designing interfaces for testability: the fixture is a pure in-process library with no external boundary to mock, so the mocking and interface-design guidance is not exercised
- T1 and T2 crediting a write the allow-list cannot see: the Bash reading is an allow-list (a call is none only when every simple command is a known read-only program with no write flag and no file redirect), so an unknown head, a script run, a target built at run time and anything unparsable all read as source writes (the shell compound constructs `for`/`while`/`until`, `if`, `{ }` and `( )` are read structurally, worst of their parts, while `case`, `select`, functions, `coproc`, `[[ ]]`, `read` and arithmetic contexts stay `source`; an unresolved expansion among a head's arguments is read-only only for a fixed list of heads that cannot write whatever they are given, and in a call with a write every `cd` target must be a plain literal path outside `src`; this was found by the first hand-run's audit, where a read-only `for ... cat` loop scored as a source write); but the reading is a heuristic and is known to credit writes in the pre-existing classes below (each classified `none` or `tests` today, each rated unnatural for an agent, none fixed in this change); the admission rule's owner audit (audited hits equal mechanical hits, clean cross-match) is the only backstop, and a T1 hit is only as trustworthy as that audit, which the list below is not exhaustive of:
  - (a) heredoc bodies with an unquoted delimiter (bash expands `$(...)`, backticks and `$NAME` in them) and heredoc text piped through a filter such as `sed` to an interpreter
  - (b) environment prefixes and wrapper options stripped without inspection (`PYTEST_ADDOPTS=--junitxml=src/x`, `GIT_TRACE=...`, `GIT_EXTERNAL_DIFF`, `PS4`, `env -S`, `exec -a`)
  - (c) `git -c <any config>` (`core.fsmonitor`, `diff.external`)
  - (d) `xargs` whose arguments come from stdin
  - (e) `sed` scripts with an address modifier or custom delimiter before `w`, GNU long-option abbreviations (`--in`), `sort`/`tree` output flags in clusters or abbreviations (`-uo`, `--ou=`), `awk` writes after `}`, `;` or a newline in the program
  - (f) output and cache path flags on pytest, mypy and ruff (`--log-file=`, `-o cache_dir=`, `--junit-xml`, `--cache-dir=`, an attached ruff `-o`)
  - (g) the inline-python scan is a blocklist: module aliases (`posix`, `vars(os)`, `sys.modules`), other libraries (`sqlite3`, `zipfile`, `logging.FileHandler`, `os.mkfifo`, `gzip.open`), `.open(path, mode)` with the mode read from the wrong positional
  - (h) python name rebinding the binding scan does not count (tuple targets, `:=`, `+=`, `for` targets)
  - (i) zsh-only expansion flags (`${(e)x}`); the Bash tool may run under zsh
  - (j) code run from agent-authored files under `tests/` (a pytest `conftest.py`, `sitecustomize`, `BASH_ENV`); cross-call state (a `cd`, a symlink or a file made in an earlier call) is invisible by design
  - (k) unproven: an unresolved expansion in the operator position of `[`/`test` on bash 4.2 or later (operator position is `source`, operand position is read-only; the latter is not shown safe on every version)
  - not a classifier gap but a speed limit: the regex that reads `sed s///` flags backtracks exponentially on adversarial input (`sed 's/` plus about 36 backslashes takes seconds, about 44 does not finish), so no timing test covers `sed` scripts
- T1 checking that the failing test covers the feature: a `touch tests/x`, an `assert False` or a token test for one behaviour satisfies a test write at or before the red, and T1 does not check that the failing test is the one that covers the feature or that every behaviour was tested first (source written for the second behaviour after one test-first cycle still hits)
- T1 and T2 over-counting writes, which costs a hit and can add a T2 cycle edit: a `src` token anywhere in a write-capable call (a heredoc body, a comment, a workdir path with a `src` segment), any head not on the allow-list (`git stash`, `git checkout`, `mkdir` outside `tests/`, `uv run <anything unlisted>`, `make`), any script run, a write whose target is not a literal path under `tests/` (`pytest | tee /tmp/out`, `rm -rf .pytest_cache`, a formatter on a bare directory), a `case`, `select`, function definition or `coproc`, `[[ ]]`, `read`, an arithmetic context, nesting past 32 open constructs, a write whose target contains an expansion (a loop variable included: `tests/$f` is `source`, `tests/literal.py` is `tests`), an unresolved expansion argument to any head outside the safe list (`sort $f`, `git log $x`, `ruff check $f`, `mypy $f`, `less $f`, `uv run pytest tests/test_$name.py`, `cd $d`, `cd "$(git rev-parse --show-toplevel)" && uv run pytest -q`, even in a read-only call), a `cd` that is not a plain literal path outside `src` in a call with a write, a `while read` loop, a summary-only red, and a command over 100,000 characters
- T3 recognising every way of flagging the planted tautological test: it reads only the final reply for a flagged note, so a flag voiced only mid-run is not seen (a repair made by any tool, Bash included, and a file moved or renamed with the line intact are read from the final python files outside `src/`)
