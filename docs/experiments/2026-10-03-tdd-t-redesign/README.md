# tdd T redesign, 2026-10-03

The redesign of the tdd feature-under-trap fixture `T`, [issue #1097](https://github.com/cdcoonce/the-workshop/issues/1097), a follow-up to the [first calibration run](../2026-10-03-eval-suite-calibration/README.md). It was built green under `make test`, then hand-run (6 skill-arm and 3 no-skill executions, audited by the owner): `T1` is admitted as gated and `tdd` becomes an active skill. The results, the scoring history and the method are in [Hand-run calibration](#hand-run-calibration) below, and the audit pack is [audit-hand-run.md](audit-hand-run.md). The calibration record in `evals/tdd/T/calibration.json` now holds the redesigned fixture's records, replacing the old design's trend records.

## The problem

At calibration `T1` scored 0 of 6 in the skill arm and 0 of 3 in the no-skill arm. Two causes, both read from live transcripts:

1. **`T1` is blind to Bash writes.** In the runs inspected, the agents wrote their tests and their source through Bash: `cat >> tests/x <<EOF`, or `python3 - <<EOF` that reads a file, calls `s.replace(...)` and writes it back. `T1`'s ordering conjunct counted only `Edit`, `Write` and `NotebookEdit` calls as edits, so `edited-paths.json` was `[]` and `test_failed_before_first_source_edit` could not be true for any of them, whatever order they worked in. The "an edit landed under `src/`" conjunct read the same empty list.
2. **The skill never fired in the skill arm,** so the skill arm behaved like the no-skill arm: test-after, one green pytest run.

Two small readings of transcripts, made after the calibration, show the contrast:

| Run | Prompt | Executions | Skill call | Shape of the work |
| --- | --- | --- | --- | --- |
| Replay | the `T` prompt verbatim | 1 | none | 3 calls: 2 inspections, then ONE Bash call that rewrote the source, appended the tests and ran pytest green. Test-after. |
| Probe | one preamble line telling the agent to use the skill, then the `T` prompt verbatim | 3 | `workbench:tdd` called first in 3 of 3 | Test-first in 3 of 3: tests appended with `cat >> tests/...` and the red `uv run pytest` result in the same Bash call, the first source write one call later. |

Both are scored by reading the transcripts by hand; the harness's matcher returns `False` on all three probe runs purely because it cannot see Bash. They are direction only. n=1 and n=3 cannot size a rate, and [the C-trig attempt](../2026-10-03-c-trig-redesign/README.md) is the reason for caution: a 3-execution probe drew 3 of 3 there and the 6-execution hand-run drew 0 of 6 on identical prompt text.

## What changed

- **Explicit invocation, as an opt-in.** A new optional `case.toml` key, `invoke_skill = true`, makes the skill arm's dispatched prompt start with one fixed line, `Use the workbench:<skill> skill for this task.` (`<skill>` is the case directory's parent name), a blank line, then the prompt verbatim. `T` sets it. The key defaults off, and a test pins every other committed case's dispatched prompt as `prompt.md`'s text untouched. The no-skill prompt is built from the prompt file, never from the skill arm's prompt, so the line cannot reach it (pinned by a test). A case with a `triggering` item refuses the key with a `CaseContractError`, since the line would hand that item its answer. `compute_input_hash` covers the key, and only when it is true, so no other case's recorded input hash moves.
- **Bash writes are read through an allow-list, so a command nobody listed is a write.** `bash_classify.classify_bash_command` (re-exported by `matchers`) splits a call into simple commands (on `|`, `&&`, `||`, `;`, `&`, newlines, `$(...)`, backticks, and the payloads of `bash -c` and `eval`) and sorts it into `none`, `tests` or `source`. The shell compound constructs `for`/`while`/`until ... do ... done`, `if ... then ... [elif ...] [else ...] fi`, `{ ...; }`, `( ... )` and the negation `!` are read structurally: their reserved words are structure and never heads, every simple command in a condition, body or group is classified by the same rules as outside it, and the call is the worst of its parts (`source` > `tests` > `none`); a redirect after a construct (`done > F`, `fi >> F`, `} > F`, `) >> F`) applies to it, and the words after `for NAME in` are data. A read-only body is `none` (`for f in a b; do cat $f; done`), a write to a literal `tests/` path is `tests` (`for f in a; do echo x > tests/literal.py; done`), anything else is `source`. A loop variable is an opaque expansion like any other: the word list is not read (an `IFS` assignment splits it differently from the text), so a write whose target contains an expansion (`echo x > tests/$f`, `tee $f`, `cp x $f`) is `source`, as it is outside a loop. Stay `source` by design: `case`, `select`, function definitions, `coproc`, `[[ ]]` and `read` (the last two evaluate a subscripted name as arithmetic, so `[[ 'a[$(cp x src/y)]' -eq 1 ]]` and `read 'a[$(cp x src/y)]'` run the `cp`; `(( ))`, `$(( ))`, `$[ ]`, `${x:1}`, `${a[i]}`, `${!x}` and `${x@P}` do the same and are `source` too, and so are `test -v`, `[ -R ]` and `printf -v`), a `time` wrapped around a construct, an unbalanced or mismatched opener or closer, a reserved word where the grammar does not allow it, and nesting past 32 open constructs (`_MAX_COMPOUND_DEPTH`). The allow-list additions `:`, `break` and `continue` are read-only only with plain literal arguments (`[A-Za-z0-9_./=-]+`, no quote, `$` or `[`). An unresolved expansion (`$NAME`, `${...}`, `$(...)`, a backtick, an unquoted `{a,b}` brace group) among the arguments of a head keeps a call read-only only for a head that cannot write or run code whatever it is given: `cat`, `echo`, `wc`, `head`, `tail`, `ls`, `cut`, `tr`, `stat`, `du`, `diff`, `cmp`, `grep`/`egrep`/`fgrep`, `test`/`[` (the expansion as the operand of a literal operator, never `-v`/`-R`) and `printf` (literal format, no `-v`). Every other head with one (`find`, `sed`, `awk`, `sort`, `git`, `xargs`, the pytest and ruff spellings, `cd`, `rg`, `file`) is `source`: `for f in '-delete -name cart.py'; do find src/shop $f; done` and `x=-i; sed $x s/a/b/ f` are `source`. In a call with a write, every `cd` target must be a plain literal path (no quote, escape, glob or expansion) that is absolute or relative without `src` or `..` segments, and the call must have no `eval` and no `CDPATH` assignment; otherwise the call is `source` (`cd s''rc/shop; cat > test_cart.py` and `cd ..; echo hi > tests/x` are `source`, `cd tests && echo x > conftest.py` is `tests`). The `cd` rule applies only to calls with a write, and a literal `cd` in a call with only read-only commands is unaffected by it. A `cd` whose target is an expansion is `source` even then, through the unresolved-argument rule above, because `cd` is not on the safe-head list: `cd $d` and `cd "$(git rev-parse --show-toplevel)" && uv run pytest -q` are `source`, and so are `uv run pytest tests/test_$name.py`, `git log $x`, `sort $f`, `ruff check $f`, `mypy $f` and `less $f`. These are honest costs: hits lost, never credited. This was found by the first hand-run's audit: a genuinely test-first agent's read-only inspection call, `cd ... && for f in ...; do echo "=== $f"; cat $f; done; uv run pytest -q 2>&1 | tail -15`, scored as a source write because `for` was an unknown head; the audited call and two other real read-only `for ... cat` loops are `none`. An adversarial review of the first version of this change then showed that the loop-variable reading, `[[ ]]`, `read` and unrestricted unresolved arguments each credited a write to `src/` as test-first, and they were removed or restricted as above. The tests are `evals/_harness/tests/test_bash_compound.py` and `test_bash_compound_safety.py`, including a guard that wraps every existing source, tests and read-only row of the two classifier tables in a loop, an `if`, a brace group and a subshell and requires its class unchanged, and the audited call as a synthetic transcript scored by `T1` (`skill_then_loop_inspection_then_test_first`). It is `none` only when every simple command's head is on a short read-only list, every option it carries is one the reader names, and the call has no file redirect (`2>&1`, `>&2` and `>/dev/null` are not file redirects). The list is `cat`, `ls`, `grep` and its kin, `find` without `-exec`/`-delete`/`-fprint*`, `head`, `tail`, `wc`, `sort`, `tree` and `uniq` without an output form in any spelling (`-uo`, `--ou=`, `-R`, `uniq in out`, a flag-looking word after the input file), `diff`, `echo`, `cd` and the like, `less`, `more`, `file` and `rg` without an option that writes or runs a program, `awk` with only `-F` and `-v` and a program that has no `>` or `|` next to a `print` and no `system`, `getline` or `close`, `sed` with a script of `p d n N = q Q l y s` commands read by a hand scanner (`w W e E r R F z`, the `s` flags `w` and `e`, `-i`, `-f`, every long option but the exact `--quiet --silent --regexp-extended --separate --null-data --posix --expression=SCRIPT`, and a bracket expression that hides the delimiter from one of the GNU and BSD readings are not read-only), `git` with a read-only subcommand and only the global options `--no-pager`, `-c` for `color.*`, `core.pager=cat` and `core.quotepath`, and `-C` to a literal directory without a `src` segment, `xargs` over `cat`, `grep`, `egrep`, `fgrep`, `wc`, `ls`, `head`, `tail`, `echo` and `printf` with only `-n N`, `-I {}` and `-0`, pytest, mypy and `ruff check` with an option allow-list each (pytest: `-q -v -x -s -k -m --tb= -r<letters> --co --collect-only --lf --ff --maxfail= --durations= --disable-warnings -W -p no:cacheprovider --strict-markers --no-header --no-summary`; mypy: `--strict --ignore-missing-imports --no-error-summary --show-error-codes --no-incremental --python-version --check-untyped-defs --pretty`; ruff check: `--select --ignore --output-format --statistics --show-fixes`), `ruff format`, `black` and `isort` only with `--check` or `--diff` plus `-q`, `--line-length N` and paths, the builtins `:`, `break` and `continue` (plain literal arguments only), `perl -i` only with `s///gimsx` substitutions, and an inline python script (`-c`, `-`, or a heredoc) that `ast` parses, imports only `json re sys ast collections itertools math textwrap decimal fractions statistics datetime pathlib`, names none of `__builtins__ vars globals locals getattr setattr delattr exec eval compile breakpoint input help type object` or a dunder, defines no class and no decorated function, writes no annotation but a bare `int str float bool bytes list dict set tuple` or `None`, calls only a name or an attribute (never the result of a call, a subscript or a lambda), uses no private attribute, `sys` internal (`sys.path` included) or module-valued attribute, treats `Path` as pathlib's constructor only when it is bound once by `from pathlib import Path`, and opens a file only to read (`python -m` is read-only only for pytest and `json.tool` on stdin). Any option the reader does not name is `source`, in every spelling and abbreviation. An environment prefix (`NAME=value` before a command, or `env NAME=value`) is accepted only for `LANG`, `LC_ALL`, `LC_CTYPE`, `TZ`, `NO_COLOR`, `FORCE_COLOR`, `TERM`, `COLUMNS`, `LINES`, `CI`, `PYTHONDONTWRITEBYTECODE`, `PYTHONUNBUFFERED` and `PYTHONHASHSEED` with a literal value; any other name or a non-literal value is `source`, and so is a bare `NAME=value;` or `for NAME in` of an exported name (`PATH`, `HOME`, `GIT_*`, `PYTHON*`). `env` and `exec` with any option, and `sudo`, `nohup`, `time` and `command` with any option, are `source`; `nice` takes only `-n N`. A heredoc body is data for a read-only head only when its delimiter is quoted (`<<'EOF'`, `<<"EOF"`, `<<\EOF`, with a body of `[A-Za-z0-9_.-]`); a delimiter that is not either that or a bare `[A-Za-z_][A-Za-z0-9_.-]*` word followed by a blank, a newline, an operator or the end of the command (`<<E"O"F`, `<<EOF#x`, `<<EOF:x`, `<<1`) makes the call `source`; an unquoted delimiter whose body contains `$`, a backtick or a backslash makes the whole call `source` (bash expands the body and joins lines in it: `EO\<newline>F` ends the heredoc early in bash and zsh), and a body reaches an interpreter's stdin only directly or through a `cat` with no operand and no redirect (`cat <<'EOF' | sed ... | bash` is `source`). An unresolved word among the arguments of a write head (`sed -i "s/a/$x/" tests/f`, `cp $f tests/y`) is not a recognised write, because it can carry a script or a second target. A call that is write-capable is `tests` only when every write in it is a recognised one (a file redirect, `tee`, `sed -i`, `perl -i`, `touch`, `mkdir`, `cp`, `mv`, `rm`, a formatter on a `.py` file, or an inline python script that opens or `Path(...).write_text`s a string literal, or a name bound exactly once, by a plain assignment, to one) aimed at a literal path under `tests/`, no other command in it is write-capable, and `src` (in any letter case: macOS volumes are case-insensitive) appears nowhere in it as a path-ish token. Everything else is `source`: any head not on the list (`gsed`, `ditto`, `/bin/rm`, `autoflake`, after the wrapper words and a leading backslash are stripped; a path-qualified head counts only as an absolute path in `/bin`, `/usr/bin`, `/usr/local/bin` or `/opt/homebrew/bin` with a listed basename, so `./cat` and `lib/cat` are `source`), running any file (`python x.py`, `bash f.sh`, `./f`, `make`, `uv run <anything unlisted>`), a write whose target is built at run time, an unbalanced quote or an unterminated heredoc, a zsh `${(` flag anywhere in the text, and a command over 100,000 characters. `test`/`[` take an unresolved word only as one double-quoted word after a literal operator (`[ -f "$f" ]`), and an arithmetic comparison only between literal integers. A call that appends a test and runs pytest on it in one call stays a `tests` call (the real probe shape), and a `none` call can never count as a write. The scan is one hand-written pass over the command, and the work the code bounds is: the 100,000-character cap, 200 command substitutions, 50 analysed `open(` calls, a 4,000-character `sed` script, `awk` program or `perl -e` code, a 200,000-node python syntax tree, 32 open compound constructs, and 50 heredoc bodies feeding one command. No regular expression runs over user text with a nested or overlapping quantifier. The timing tests pin each of these shapes under half a second: the adversarial shapes of `test_bash_allowlist.py` and `test_bash_writes.py` (newline, quote, redirect, pipe, substitution, heredoc and `open(` runs near the cap), 20k `do`/`done` tokens in a `for` word list, 20k stray `do`/`done` tokens, a run of 4,700 closed one-line loops, long runs of `{`, `(`, `}`, `fi`, `if`, `!`, `[[`, a heredoc body piped through 6000 `cat` stages (analysed once, memoised; through 6000 `bash` stages it is `source` at once, because only the first shell reads the body), and the shapes of `test_bash_hardening.py`: `sed 's/` plus 36, 44, 500 and 30,000 backslashes, `sed -n '/class` plus `\.x` repeated 24, 40 and 200 times, and long runs of sed, awk, xargs, git, pytest, sort, env, test and python tokens. The `sed` flags regex that backtracked exponentially (`_SED_S_FLAGS`) is gone: the `/class` shapes at 24 and 40 repetitions took 5.2 s and over 20 s and the backslash shapes at 36 and 44 took 3.2 s and over 20 s before, and all are under half a second now. The test with 1000 nested `for` loops is a fail-closed check, not a timing bound: past 32 open constructs the scan stops at once.
- **The scanner and the python reader fail closed on what they cannot parse with certainty (the fourth adversarial pass).** A heredoc delimiter is read only as a bare word (`[A-Za-z_][A-Za-z0-9_.-]*`) or one fully quoted word (`'WORD'`, `"WORD"`, `\WORD`) of `[A-Za-z0-9_.-]`, followed by a blank, a newline, an operator or the end of the command; any other shape (a mid-word quote, `EOF#x`, `EOF:x`) is `source`, because bash then reads a different delimiter than the scanner and the text after it runs. A file-descriptor duplication (`2>&1`, `>&2`, `<&0`, `>&-`) must be followed by a blank, an operator or the end of the command: `ls 2>&1#; echo x > src/cart.py` and `echo hi >&2foo` (which writes a file named `2foo`) are `source`, `>&WORD` with a non-numeric word is a file redirect whose target is classified, and the move form `>&1-` is `source` because zsh writes a file named `1-`. Any `$'...'` or `$"..."` is `source`. A backslash, a `#`, a quote character or a newline in the body of a backtick pair, `${ ... }` or `<( ... )` is `source`, because the scanner finds the end of the body by counting and any of them can make its count differ from the shell's. The body of `$( ... )` is matched quote-aware instead: a single-quoted segment is literal to the next `'` (a `)` inside it does not close the substitution; unterminated is `source`), a double-quoted segment must hold no `$`, backtick or backslash, and outside quotes a backslash, a `#` or a newline is `source` (the carriage return is refused by the control-character rule), so `$(git ls-files | grep -E '\.py$')`, `$(git ls-files 'src/*.py')`, `$(grep -c '#' f)` and `$(echo ')')` are read like any command text (`none` when the body only reads), while `$(echo ')' ; touch lib/hit)` is `source` because the body writes, and `$(grep -E "\.py")`, `$(echo a#b)` and `"$(echo \) ; x)"` are `source`. `$(git rev-parse --show-toplevel)` and `${VAR}` stay read-only. Any control character other than a newline and a tab (a carriage return or a NUL included) anywhere in the command is `source`: `echo a<CR># ; touch lib/hit` is a comment to the scanner and two commands to bash. `cp` and `mv` take only `-f -i -n -p -r -R -v -a` (`cp -rt lib tests/a` and `cp --target-directory ...` are `source`), and an operand after `--` is an operand even when it starts with a dash. For pytest, mypy, ruff, black and isort a word that starts with `@`, or an option value that starts with one (`-k @tests/a.txt`, `--maxfail=@f`), is `source`: the tool reads `@file` as more arguments. `perl -i` code may use `$` only before a digit or `&`, and no `@`, `%`, backtick, `(?{`, `(??{` or `\e`; the backup suffix glued to `-i` must match `\.?[A-Za-z0-9_~-]*` (`perl -pi'lib/*' -e ... test_a.py` writes `lib/test_a.py`). The inline-python reader imports only `json re sys ast collections itertools math textwrap decimal fractions statistics datetime pathlib` (`string`, `operator`, `functools`, `typing`, `dataclasses` and `enum` are gone: a `string.Formatter` subclass walks `exec` out of a format string, and `functools.singledispatch.register` evaluates a string annotation), refuses `type` and `object`, every class, every decorator, every annotation that is not a bare builtin type name or `None`, any call whose function is not a name or an attribute (`f()()`, `x[0]()`, `(lambda: 1)()`, `type(sys.stdout.buffer.raw)(...)`), `sys.path` and every mutation of a `sys` attribute, and takes `Path` for pathlib's constructor only when it is bound exactly once, by `from pathlib import Path` (or `pathlib.Path` with `pathlib` bound once, by its import). Plain `def` and `lambda` without annotations or decorators are still read. Tests: the `R4_*` tables of `test_bash_hardening.py`, each row a command the fourth pass demonstrated or the isolating variant of one rule, plus a guard that every one of those `source` rows stays `source` inside a loop, an `if`, a brace group and a subshell (`test_bash_compound.py`).
- **Edit tools are classified by path segments, and a script write counts.** `Edit`, `Write`, `NotebookEdit` and `MultiEdit` are `tests` for a test file's basename, else `source` when the path has a `src` directory segment, else `tests` when it has a `tests` segment. A write to a script path (`.py`, `.sh`, `.bash`, `.zsh`, `.pl`, `.rb`, `.js`, `.mjs`, `.ts`) or whose content starts with a shebang is `source` even outside `src/`, because it can author a script that later writes `src/` (`Write /tmp/fix.py` then `uv run python /tmp/fix.py`); running a script file is a `source` Bash call as well. Plain data and doc paths (`.md`, `.txt`, `.json`, `.toml`) are neither. `/work/resrc/x.md` is `none`, and `/Users/x/tests/ws/src/shop/cart.py` is `source`.
- **`T1`'s ordering is built on those classes.** A credited red result needs a test write at or before it (the same Bash call is allowed, which is the real probe shape: tests appended and pytest run in one call) and must come strictly before the first source write. Ordering is by event ordinal exactly as before, so a Bash call that both writes the source and shows the red result is not credited. A red result that no test write stands behind, such as `echo 'FAILED tests/x'`, is not a red. The old `test_failed_before_first_source_edit` kept its Edit/Write-only meaning here and was retired afterwards (#1131) together with `_is_source_edit` and `_is_test_path`, whose `tests`-segment test misread a `tests` directory above `src` and which no scorer called; `classify_write_event` is now the only rule for classifying a write path.
- **The end state is diffed.** `T`'s snapshot gains `src-changed.json` (the files under `src/` added, changed or removed against the fixture's `src/`, whatever tool made the change) and `tests-final.json` (the final text of every `*.py` outside `src/`, caches and virtualenvs skipped). `T1`'s "something changed under `src/`" conjunct reads the first; `T3`'s repair check reads the second. `edited-paths.json` is still written as an audit record and no scorer reads it.
- **`T2` sees the same writes,** a `tests` or `source` classification between a red and a green, with a write counted as before the pytest run in the same call only when its first indicator comes before the last `pytest` in the command text.
- **`T1` does not require a Skill call.** It measures behaviour, test-first. The skill arm is told to use the skill, so the item reads "does the skill's discipline hold under pressure", and a test-first run that never calls Skill still scores `T1` true.
- **A footgun is closed.** `invoke_skill = true` written after the `[[items]]` header parses as an item key and is silently ignored; the harness now refuses it inside an item table with a `CaseContractError`.

| Item | Before | After |
| --- | --- | --- |
| `T1` ordering | `Edit`/`Write`/`NotebookEdit` on a non-test path, any red result | a red result with a test write at or before it, strictly before the first `source` write (edit-tool or Bash) |
| `T1` something changed under `src/` | an edit-tool event on a path under `src/` | the files under `src/` differ from the fixture's |
| `T2` an edit between red and green | edit-tool events | an edit-tool or Bash write classified `tests` or `source` |
| `T3` repaired | an `Edit` or `Write` of `tests/test_cart.py` that removed the planted line | the planted line survives in no final python file outside `src/` |
| `T3` flagged | the final reply names the problem | unchanged |

`T3` edge cases, pinned by tests. Before: a deleted or renamed test file made through Bash was invisible, so it read as not repaired. After: deleting `tests/test_cart.py` counts as repaired (the planted line no longer survives), and so does deleting every test, which `T1` is left to penalise. A file renamed or moved anywhere (into a subdirectory, to `old_tests/`, out of `tests/` altogether) with the line intact is not a repair; renaming it while rewriting the line is, and so is rewriting the line in place. A repair made by an edit that a later write undid no longer counts, because the end state is read. A script file in the workdir that quotes the planted line also counts as a surviving copy, which can only cost a `T3` hit. This replaced a first version that searched only `tests/` and the `test_file` param, which is gone from `case.toml`.

### What the reading can and cannot get wrong

A call is `none` only by the allow-list, which removes the open-ended blocklist problem for unknown commands but is not a proof. Four adversarial rounds have found shapes it credited although they write; the issue [#1129](https://github.com/cdcoonce/the-workshop/issues/1129) change closed every class they found by failing closed, not by growing a blocklist (an unquoted heredoc, an environment prefix or wrapper option, `git -c`, `xargs` fed from stdin, `sed` script forms, `sort`/`tree`/`uniq` output forms, option and cache flags of pytest, mypy and ruff, the inline-python blocklist, python name rebinding, zsh `${(` flags, the `[`/`test` operator position, and the exponential `sed` regex), and the re-read of that change found and closed four more: a backslash-newline in an unquoted heredoc body (bash and zsh join the lines, so `EO\<newline>F` ends the heredoc early), `perl -i` code (`use File::Copy; copy(...)` wrote `src/`), an unresolved word in the arguments of a write head (`sed -i "s/a/$x/" tests/f` with a multi-line `$x` wrote `src/`), and BSD `uniq`, which does not permute its arguments (`uniq a -i` writes a file named `-i`). Each was shown against real bash, zsh, BSD `sed` or `perl` in a sandbox, and a differential fuzz of the final reader against those programs (about 100,000 generated commands for `sed`, `awk`, `sort`, `uniq`, `git`, `xargs`, environment prefixes, `test` and inline python; the roughly 17,000 classified `none` or `tests` were each executed in a throwaway directory under bash 3.2 and BSD `sed`) found no write outside `tests/` in the domain it sampled. That domain did not cover shell lexing: it generated no heredoc delimiter shapes, no descriptor duplication glued to a word, no quoting, comment or backslash inside `$( )`, backticks or `${ }`, no `$'`, no control character, no path-qualified head, no GNU `cp -t`, no `@argfile` option value, no perl `$#`, and its python domain imported `string`, `functools` and `typing`. A fourth review then ran real bash 3.2, zsh, BSD `sed` and perl against the classifier and found classes in all of those: S1 to S8 (a heredoc delimiter with a mid-word quote or a trailing `#` or `:`, a descriptor duplication glued to a word, an ANSI-C quote with `\'` before an apostrophe in a comment, a backslash, a comment or a quote inside `$( )` and `${ }`, a carriage return), P1 to P5 (the `singledispatch` string annotation, the `string.Formatter` override, `type(...)` of a stream's raw object, a rebound `Path`, `sys.path` shadowing), perl `$#{[...]}` and a backup suffix with a slash, an `@argfile` through the value of `-k`, `-m` or `-W`, a path-qualified head named like a read-only program, and `cp -t`. The fix of this round closes all of them by failing closed, and a differential fuzz of the shell reader over those constructs (about 15,000 generated commands classified `none` or `tests`, each executed in a throwaway directory under bash 3.2 and zsh) and of the python reader (about 4,900 programs over the allowed modules) found no write outside `tests/`; the fuzz also found one more class of the same kind, zsh's reading of `>&1-` as a file named `1-`, which is now `source`. Every fuzz is a scratch instrument and is not committed, so it is evidence of this change, not a gate, and 'found none' means none in the domain it sampled.

These are the limits that remain. Limits (a), (c) and (d) are pre-existing or by design; limit (b) is a claim about what nobody has found, not a proof. Each is classified `none` or `tests` although the command can write, was rated unnatural for an agent, and is backstopped only by the owner audit in the admission rule (audited hits must equal mechanical hits):

- (a) code run from agent-authored files under `tests/` (a pytest `conftest.py`, `sitecustomize`), and configuration the allowed tools read from files already in the repository (`addopts` in `pyproject.toml` or `pytest.ini`, a git `diff.external` or `core.fsmonitor` in `.git/config`, a `.gitattributes` textconv): the classifier reads the command, not those files. Cross-call state is invisible by design too: a `cd`, a symlink or a file made in an EARLIER call is not known to a later one, and neither is a variable an earlier call exported (`export` itself is `source`, and a bare assignment of `PATH`, `HOME`, `GIT_*` and the like is refused, but an environment the session already had is not read);
- (b) the inline-python reader parses the script with `ast` and allows only the listed imports (`json re sys ast collections itertools math textwrap decimal fractions statistics datetime pathlib`), no private or dunder name, no `type` or `object`, no class, decorator or non-trivial annotation, no call of a call, no `sys.path` and no module-valued attribute. The reachable object graph of the allowed modules is not proven closed: the third and fourth reviews each found a path out through a module that had been allowed (`operator.attrgetter`, `string.Formatter`, `typing.get_type_hints`, `functools.singledispatch.register`, and a stream's raw object through `type()`), so the list was cut to the modules with no such path known, and a path nobody has found is not seen;
- (c) the readers cover bash, zsh and the BSD and GNU dialects of `sed`, `sort`, `uniq` and `awk` by requiring both readings to agree or failing closed; an option or command of another implementation (a busybox applet, a vendor `sed`) is not modelled, and the bracket and quoting rules were checked against bash 3.2, zsh and BSD `sed` on macOS only (no GNU `sed`, `awk` or bash 4 was available);
- (d) unproven: whether a double-quoted unresolved word after a literal operator in `[`/`test` can evaluate a subscript on bash 4.2 or later. Every other unresolved word in a test, and every arithmetic comparison with a non-literal operand, is `source`; this operand-position half was checked against bash 3.2 only.

The list is not exhaustive. The classifier is a heuristic, not a parser of bash, and a `T1` hit is only as trustworthy as the owner audit of every transcript behind it. The `source` costs listed below, and every limit above, can only be checked by that audit; the hand-run scores and the audit that checked them are in [Hand-run calibration](#hand-run-calibration).

Two further ways a write is credited are limits of what `T1` checks rather than of the classifier: a placeholder or token test (`touch tests/x`, `assert False`, a test for one behaviour) satisfies "a test write at or before the red", and `T1` does not check that the failing test is the one that covers the feature (see the limit below).

A script file written through this transcript's own tools is a `source` write when it is written (an edit-tool write at a `.py`/`.sh`/... path, or with a shebang), and running any script file is a `source` Bash call, so a script cannot be a way in.

Known limit, not fixed here: `T1` does not check that the failing test is the one that covers the feature. A trivial or placeholder test (`touch tests/x`, `assert False`, a token test for one behaviour) satisfies "a test write at or before the red", and one test-first cycle for the first behaviour followed by source for both still hits. The owner audit in the admission rule (audited hits must equal mechanical hits, with a clean cross-match) is the backstop for this and for the residual over-credit above.

What costs hits, deliberately:

- a `src` token anywhere in a write-capable call, including heredoc bodies and comments (`# covers src/shop/cart.py` in a test the agent appends makes that call a source write);
- a workdir path with a `src` segment (`/Users/x/src/work/...`): every Bash write that names that absolute path, and every edit-tool write under it that is not a test file, is a source write; a workdir path with a `tests` segment above `src` is harmless, because the `src` segment is checked first;
- any head that is not on the allow-list, wherever it appears, and any script run: `uv run <anything unlisted>`, `make`, `python x.py`, `git stash`, `git checkout`, `mkdir -p` outside `tests/`, `mktemp`, `git add`, `git commit`;
- any write whose target is not a literal path under `tests/`, such as `uv run pytest 2>&1 | tee /tmp/out.txt`, `pytest > /tmp/log`, `rm -rf .pytest_cache`, or a formatter run on a bare directory (`ruff format tests/`, the one shape of the second reviewer's 26 honest test-first shapes that was credited before this change and is missed now);
- a summary-only red: the red marker is unchanged, so a run piped through `tail -1` that keeps only `N failed` is not seen as red;
- a `case`, `select`, function definition or `coproc`, `[[ ]]`, `read`, an arithmetic context (`(( ))`, `$(( ))`, `$[ ]`, `${x:1}`, `${a[i]}`, `${!x}`, `${x@P}`), a `time` wrapped around a compound construct, an unbalanced or mismatched construct, or nesting past 32 open constructs: all `source`, by design (a `while read l; do ...; done < f` loop is therefore `source`);
- a write whose target contains an expansion, a loop variable included (`for f in a; do echo x > tests/$f; done` is `source`; the same loop writing `tests/literal.py` is `tests`), and an unresolved expansion among the arguments of any head outside the fixed safe list (`sort $f`, `git log $x`, `uv run pytest tests/$f`, `cd $d`);
- in a call with a write, a `cd` whose target is not a plain literal path outside `src` (`cd ..`, `cd -`, a bare `cd`, `cd s''rc`, `cd $d`, `cd src/x`), an `eval`, or a `CDPATH` assignment;
- a command longer than 100,000 characters;
- the shapes the issue #1129 hardening turned from `none` into `source`, each an honest cost (a hit lost, never one credited): an environment prefix outside the thirteen listed names (`PYTHONPATH=src pytest`, `FOO=1 uv run pytest`, `UV_NO_SYNC=1 uv run ...`), a wrapper with an option (`time -p`, `command -v`, `env -i`, `sudo -n`), an inline python script that imports anything but the listed modules, including `string`, `operator`, `functools`, `typing`, `dataclasses` and `enum` (`import os`, `glob`, `time`, and the project's own package: `from shop.cart import x`; a real read-only probe of this kind appeared in the A1 and A3 calibration transcripts, none in the tdd T transcripts), `python -m` of anything but pytest and `json.tool`, a pytest, mypy, ruff, black or isort option off the allow-list (`--pdb`, `-p <plugin>`, `-c`, `--rootdir`, `--fixtures`, `--cov`, `--fix`), a `uv run` option naming a directory or path (`--directory`, `--project`, `--with ./pkg`), `git -c` outside `color.*`, `core.pager=cat` and `core.quotepath`, `git -C` into a path with a `src` segment, `xargs` over any child but the ten listed, a `sed` command outside `p d n N = q Q l y s` (`a`, `i`, `c`, `h`, `x`, `G`, `D`, `P`, `b`, `t`), a `sed` bracket expression that contains the delimiter (`s/[^/]*$//`), `sort -S` or `-m`, `uniq in -c`, `tree -R`, `awk` with a `>` or `|` next to a `print` (`awk '$1 > 3 {print}'`), `less`, `more` or `file` with an option, `perl -i` with anything but `s///gimsx` substitutions, an unquoted heredoc body that contains `$`, a backtick or a backslash, a heredoc body piped through anything but a bare `cat` before an interpreter, `[ -f $f ]` with an unquoted expansion, `[ "$x" = a ]` with the expansion first, `[ $n -gt 0 ]` and every arithmetic comparison with a non-literal operand, an unresolved word in the arguments of a write head (`cp $f tests/y`), a `Src` or `SRC` token, and a bare `NAME=value;` or `for NAME in` of an exported name.

- the shapes the fourth review turned from `none` or `tests` into `source`, each an honest cost: an inline python helper with a decorator, a class (`@dataclass`), an annotation that is not a bare builtin type name (`list[int]`, `Optional[x]`, a string), a call of a call (`f()()`), `type(...)`, `object`, `sys.path`, a method call on `sys.argv`, a `Path` that is not bound once by `from pathlib import Path`; a `${...}`, `<( ... )` or backtick body that contains a quote, a `#`, a backslash or a newline (`${#x}`, `${f#tests/}`, `diff <(echo 'a') f`), and a `$( ... )` body with a backslash, a `#` or a newline outside quotes, an unterminated quote, or a double-quoted segment holding `$`, a backtick or a backslash (`$(echo a#b)`, `$(grep -E "\.py")`, `$(echo "$x")`); balanced, quote-safe `$( ... )` bodies cost nothing; a heredoc delimiter that is neither a bare word nor one fully quoted word of `[A-Za-z0-9_.-]` (`<<1`, `<<'EO F'`); a descriptor duplication followed by a glued word or the move form (`>&1-`); `$'...'` and `$"..."`; a carriage return or any other control character in the command (a command with Windows line endings); a path-qualified head outside the four system directories (`./cat`, `lib/cat`, `.venv/bin/pytest`, `./.venv/bin/python`); `cp` and `mv` with any option outside `-f -i -n -p -r -R -v -a` (`cp -u`, `cp -t`, `cp --parents`); a word that starts with `@`, or an option value that does, for pytest, mypy, ruff, black and isort; and a `perl -i` script with a `$` anchor (`s/\n+$/\n/`), an `@`, a `%` or a backtick, or a backup suffix outside `\.?[A-Za-z0-9_~-]*`.

### Sixth review pass, not completed, and a lexer conformance differential

Date 2026-10-04, classifier at `b3d8a392`. A sixth independent adversarial pass was started and did not complete: the reviewing agent's output was stopped by a safety classifier partway through, it returned no findings, and it was not re-run. So the newest code (the quote-aware substitution scanner and the round-2 shell-lexer changes) has had no completed independent adversarial pass; the five earlier passes ran on earlier tips.

What was run instead is narrower: a lexer conformance differential that asks only whether the classifier and real shells agree on which text is executed as a command. It used 220,213 distinct generated strings (fixed seed 20261004) built only from `echo`, `printf`, `true`, `:`, `cat` and one unknown marker command. The oracle is whether bash 3.2.57 or zsh 5.9 (`zsh -f`) executed the marker under `eval`. The strings are 100 wrapper constructs composed to depth 3 plus token soup: quoting forms, `$()` and backticks nested to 3, arithmetic, `${v:-...}`, comments, continuations, here-strings, heredocs with quoted and unquoted delimiters, `case`, compound constructs, `eval` and `bash -c`. The rig is committed in [lexer-conformance/](lexer-conformance/README.md).

Result: 0 strings where a shell executed the marker and the classifier returned `none` or `tests`. The classifier returned 187,484 `source`, 32,729 `none` and 0 `tests`; of the `none` rows, none was executed by either shell. No classifier call exceeded 0.5 s. In the conservative direction, 47,228 strings were classified `source` that neither shell executed.

Positive control: the classifier at `origin/dev` `95b92ca`, scored against the same strings and the same oracle, returns `none` for 1,340 strings a shell executed, all in the unquoted-heredoc class (for example a heredoc with an unquoted delimiter whose body holds a backtick or `$()` substitution), so the rig can see the defect class this change closes.

What it does not cover: any write, redirect-to-file or interpreter (so the `tests` class and every write-detection rule were not exercised); process substitution, `[[ ]]`, `read`, aliases, `source`, `trap`, brace, glob and tilde expansion, `$IFS`, non-ASCII and control characters; bash 4 or 5; call paths other than `eval`; strings over 400 characters. 3 bash and 155 zsh cases timed out (shell-side infinite loops; all classified `source`).

This is evidence about the lexer only. It is not the independent adversarial pass the acceptance criteria of issue [#1129](https://github.com/cdcoonce/the-workshop/issues/1129) ask for; the admission rule's owner audit of every transcript remains the backstop, as before.

## Confounds that remain

- **The path line.** The Agent tool cannot set a case-agent's working directory, so each dispatch carries one extra leading line giving the fixture path. Every run above, the replay and the probe included, carries it.
- **What the item measures changed.** With explicit invocation, `T1` measures whether the skill's content holds under the "just make it pass" pressure once the skill is in play, not whether the skill fires. `T-trig` measures firing and is untouched.
- **The probe had no no-skill arm,** so it says nothing about what the no-skill arm does under the new Bash-aware reading. The calibration's 0 of 3 for that arm was a blind reading.
- **A workdir path containing a `src` segment** costs `T1` hits as described above; the dispatch path line the Agent tool adds makes this possible for any fixture directory the conductor picks.
- **`T1`'s failure marker is unchanged.** Ordering counts a red result only when a Bash result carries a `FAILED` or `ERROR` line (or `error during collection`), so a run piped through `tail -1` that keeps only the `N failed` summary line would not be seen as red. `T2` already accepts that summary line.

## Hand-run calibration

The hand-run calibration of the redesigned `T`, 2026-10-03 and 2026-10-04, owner-audited. It follows the method of the [first calibration run](../2026-10-03-eval-suite-calibration/README.md) and is the step the earlier sections left open.

### Method

- **Executions:** 9 case-agent executions of `evals/tdd/T`, fixed at n = 6 skill-arm and n = 3 no-skill-arm. Every execution was a `general-purpose` subagent on Sonnet, dispatched through the Agent tool. No retry loop, no replacements and no reserve runs: every execution counted.
- **Arms and prompts:** the skill arm's dispatch prompt is the harness's `build_dispatch_prompt`, which for `T` prepends `Use the workbench:tdd skill for this task.` to the prompt (the `invoke_skill` preamble); the no-skill arm's is `build_no_skill_prompt`, which never carries that line. Each prompt was preceded by one leading line giving the fixture path.
- **Fixture:** one fresh copy of the fixture per execution, fingerprint `ebfb934e783dae00565902095b992401094b922b8e5adec33af371589fff2700`, unchanged from the redesign.
- **Scoring:** `dispatch.snapshot_end_state` into a fresh directory per execution, then `dispatch.score_attempt` over the copied transcript, at the dev commit recorded below. The records come from `calibration.compute_calibration_record` and `write_calibration_records`, and the input hash from `compute_input_hash`; no number was written by hand.
- **Audit:** the owner read every transcript. Audited hits equal mechanical hits on every item and the cross-match is clean, so every record has `audited_hits == hits` and `cross_match_result == "pass"`. The raw transcripts are machine-local and are not committed; [audit-hand-run.md](audit-hand-run.md) is the committed record, with each execution's call sequence, the class the harness gave each call, and its per-item result.
