**Finding 1** (new-file line 115, `return first_unpushed + 1`): `classify_pushed_prefix` returns one more than the actual length of the leading pushed run. Traced against `test_collapses_three_unpushed_commits_into_one` (3 unpushed commits, remote branch absent → `pushed_flags=[False,False,False]`): `first_unpushed=0`, function returns `0+1=1` instead of `0`. The result: that commit is left standing unsquashed while only the remaining two collapse, contradicting the diff's own test assertions (`pushed==0`, `unpushed==3`, `squash_base==base`).

**Finding 2** (new-file line 207, `pushed_flags = [_is_ancestor(remote_head, sha) for sha in session]`): the ancestry check's arguments are reversed. It should ask "is `sha` an ancestor of `remote_head`" (i.e., is this local commit already contained in the remote's history) but instead asks "is `remote_head` an ancestor of `sha`" — nearly the opposite question. Traced against `test_all_session_commits_pushed_is_a_no_op` (2 commits, both actually pushed, `remote_head` = the second/newest commit `c2`): for `sha=c1` (the older, also-pushed commit), the check asks "is `c2` an ancestor of `c1`" — false, since a later commit can never be an ancestor of an earlier one. This yields `pushed_flags=[False, True]`, which `classify_pushed_prefix` flags as an "interleaved" ambiguous pattern and reports `skipped`, even though every commit was genuinely pushed — contradicting the test's expectation of `action == "none"`.

Both defects sit squarely in the ancestry-test/pushed-prefix-classification path the lens targets, and both are independently reachable (the second doesn't require the first to manifest, since the `remote_head is None` branch bypasses it).
