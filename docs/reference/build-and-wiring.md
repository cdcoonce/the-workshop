# Build & Wiring Reference

How the plugin is assembled from source, and how hooks are wired into Claude
Code's lifecycle. The prose here is hand-written; the tables are generated by
`scripts/stamp.py` from the actual scripts and settings, so they never drift
from what the repo does. Run `make stamp` after changing a script or hook.

## The build model

There is no composition step and no separate output tree. Each directory under
`plugins/` **is** a shipped plugin, and the platforms read it straight from
source. The flat reorg (#650/#656) deleted `core/`, `presets/`, `dist/`,
`build_preset.py`, and `build_docs.py`; nothing is copied anywhere.

Membership is the filesystem. A plugin ships exactly the skills in its own
`skills/`, the agents in its own `agents/`, and the hooks in its own
`hooks/scripts/`. No manifest field declares what to include, and one plugin
cannot inherit a component from another.

`scripts/stamp.py` is the only build component. It owns a fixed map of generated
paths, renders each from hand-written source in the tree, marks every file it
writes, and refuses to overwrite a file lacking its marker — so a mis-mapped
output cannot silently consume hand-written work. Anything not in that map is
hand-authored. It is deterministic and idempotent, which is what lets `make test`
gate on staleness via `make stamp-check`.

One tree is deliberately outside that map: `plugins/workbench/machinery/rendered/`
is generated by `machinery/tools/wiring_gen.py`, which `stamp.py` does not
invoke. Running `make stamp` will not refresh it. `TestRenderedTreeFreshness`
re-renders it and asserts byte-equality on every run, so drift is caught — but
the repair is to run that tool directly.

## Hook wiring

Hooks are Python scripts under `plugins/<name>/hooks/scripts/`. Dropping a
script there **is** the wiring: each declares its own event in a top-level
`WORKSHOP_HOOK` dict, which `stamp.py` reads statically with `ast` and renders
into that plugin's generated `hooks/hooks.json`. There is no settings file to
edit and nothing to merge — a plugin that ships no hook scripts gets no
`hooks.json` at all.

A file whose name starts with `_` is a shared library module rather than a hook
(see `hooks/scripts/_git_baseline.py`); hook discovery skips it, and so does the
component inventory the version gate reads.

The event a hook runs on is decided by its wiring, not its name — the table below
is derived from the settings, so it reflects reality even when a hook's docstring

## Keeping this in sync

`make stamp-check` renders the same path map in memory and fails, naming the
file and printing a diff, on anything committed stale. `make test` runs it, so a
component change not accompanied by regenerated output turns the build red.

`make test` also runs the version-bump gate, which is the other half of shipping:
a plugin whose hand-authored content changed must also declare a new version, or
`claude plugin update` offers nothing and the change reaches nobody who has it
installed. See the repo README's Development section for the full loop, and
Plugin Versioning in CLAUDE.md for which position to move.
